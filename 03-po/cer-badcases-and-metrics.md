# CER 真实指标 & Badcase 库

> 来源：记忆导出 2026-05-31（§2.4 / §2.5）。这是 [[03-po/README]] 指标体系在真实项目 CER 上的落地实例，也是面试 Q8/Q9/Q10 的弹药。

## 关键指标

| 指标 | 数值/口径 | 用途 |
|------|----------|------|
| 自动化覆盖率 | **70%** | ROI / executive presentation |
| 准确率 | **90%+** | 同上 |
| 项目工时节省 | **~8 天/项目** | 同上 |
| **漏检率 = 1 − recall** | 线上红线指标 | 「差异识别」环节，真实存在的差异被系统漏掉的比例 —— 监管场景最怕被罚 |
| 质量门（OpenClaw 侧 LENS） | Q3 无幻觉 + 90–95% 覆盖率 | MAE 角色矩阵的关键质量闸 |

> ⚠️ 记不清/不确定：各 BU 实测漏检率、AB 参数等更细的精确数值，导出片段未给出。

## 5 类真实 Badcase（CER 差异定位）

> 这 5 类已沉淀进 Prompt 的「自检负例」（见 [[02-architect/prompts/cer-diff-prompt]] 的 Step 4 + 负例 A–E）。

| 编号 | 现象 | 自检方法 |
|------|------|---------|
| **A** | 表格整合成段（把含表格的整段当"新增"整体标记，对应内容丢失） | 检查定位符内是否含 `TableJSON_START` 或超 3 行，是则按行重处理 |
| **B** | 定位符为空（`<<- ->>` / `<<~ ~>>` 内无内容） | 扫描所有定位符，确认 `<<…>>` 之间有非空文本 |
| **C** | 原文被改写（去掉定位符后与原文不逐字一致） | 去掉定位符后剩余内容必须与原始输入逐字一致 |
| **D** | 定位符嵌套（`<<- 设备A <<~ 参数B ~>> ->>`） | 从左到右扫描，遇第二个 `<<` 前必须已出现对应 `>>` |
| **E** | 两侧完全一致仍加标记 | normalize 后一致则不得出现任何定位符 |

## 其他 Badcase
- **数值空格误判**：`0.327% ±15%` vs `0.327%±15%` 因空格被误判为变化 → 需 `normalize_cell` 去空格再比对。
- **幻觉/夸大**（OpenClaw/SAM 侧）："说但不做（says but doesn't do）"、凭空捏造"内部测试验证"等不存在的结论 → 正是「窄 Agent + HITL，不在信任未建立前放手」的理由。

## 关联结论（指标 → 决策）
- **现在不微调（SFT）**：先建采反馈闭环积累干练样本，few-shot/RAG 优先；修正信号进 exemplar 库 / gold set / falsification 集，**不动 prompt**。没微调，模型本身永远不会跑自嗨；是周边检索/schema/白名单兜自嗨。
- **关键纪律**：含有修正信号别"新 prompt 重来一遍"（会污染 context、不 scale）。
